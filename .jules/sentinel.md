## 2023-10-27 - [CRITICAL] Prevent Python Interpreter Crash from Rust Panics
**Vulnerability:** The Rust PyO3 bindings previously used `panic!()` to handle unrecognized or unparseable feature string inputs. When called from Python, these unhandled panics would ungracefully abort the host Python interpreter process, creating a critical Denial of Service (DoS) vulnerability when exposed to untrusted input.
**Learning:** Panics crossing the Foreign Function Interface (FFI) boundary, especially those reachable via user-supplied arguments, constitute a severe stability and security risk. Rust code exposed via PyO3 must carefully validate input and map failures to proper Python exceptions rather than aborting.
**Prevention:** Instead of implementing `From<String>` which may panic, parse input using `std::str::FromStr` which returns a `Result`. On the PyO3 boundary (e.g., inside `#[new]` constructors), use the `?` operator or explicitly handle `Result::Err` to return an appropriate `PyErr` (like `PyValueError`). This ensures Python correctly catches the error as an exception rather than crashing the runtime.
